# Connected accounts

Use `connector_status` for content-free readiness and `summary_job_status` for an owner-issued opaque job ID. These tools never return conversations, titles, senders or summaries. Open the human view for fictional chat selection/results. Real chat is not connected. No provider replacement or fallback is permitted.

## Set up the owner's Google app

**Whose account:** the owner's own main Google account owns ONE Google Cloud project and Web OAuth app. Your wizard needs NO Google account. The app is only a permission key, holds no Google data, and connects all the owner's accounts. Default to **External + In production**; only choose **Internal** when the owner is a company Workspace administrator and wants organization-only access.

1. Call MCP `google_app_setup_status` with `{}`. It returns the exact redirect URI, configured/managed flags, required APIs/scopes — no client credentials. If already configured, do not create or replace anything: help the owner connect accounts. Environment-managed credentials belong to the installer.
2. Open `https://console.cloud.google.com/auth/overview` in the preserved **Wizard Browser** (the shared headful browser, not a separate headless session). Use its supported private phone takeover/human-handoff. Ask the owner to sign into **their own main Google account**. If this is their first Cloud visit, they must review and accept Google's Cloud terms themselves. Never create an agent Google account. Never request a password, OTP, or client secret in chat.
3. Pause ALL screenshots, DOM/accessibility reads, console/trace/recording and automation while the owner signs in, accepts legal terms, approves identity/consent or handles billing prompts. Wait for them to say done. Preserve the browser; do not restart an uncertain submitted step. Billing is not needed: stop, do not buy anything.
4. After sign-in, run the shipped `scripts/google_cloud_setup.py --dry-run` against that same browser, through the platform's handoff runner if available (it injects `HANDOFF_CDP_URL`), otherwise with `BROWSER_CDP_URL` pointing at the Wizard Browser's existing CDP. Playwright's Python package is required in that runner. Never enable Playwright tracing/debug/page dumps: client credentials appear on the creation screen.
5. Call MCP `google_app_setup_begin` with `{}` **after sign-in**. It returns a 30-minute, single-use **internal** intake URL (capability in its fragment), expiry and redirect URI. A new begin invalidates the old one. Pass these as `GOOGLE_SETUP_INTAKE_URL` and `GOOGLE_SETUP_REDIRECT_URI` to the script, not provider secrets. Run in the Wizard service network where `wizard-connectors-calendar:8799` resolves, or through a private loopback tunnel to that ingress; never expose intake through a public/proxied browser URL. No provider credentials need to be visible to the model.
6. Run the shipped script with default `--step all`. It reuses an existing Wizard project/client, enables Calendar API, fills branding/contact from the signed-in owner, chooses External and publishes to production, creates Web client Wizard with the exact redirect URI, and deposits ID/secret **directly** into Connected accounts. No secrets are printed, saved in the script's state file, copied through a clipboard, or returned by MCP. The state file holds only a public project ID. The broker remains the sole encrypted durable custodian.
7. A JSON `needs_owner` result is a STOP, not permission to guess. Return the same browser to the owner with one action; pause inspection again. In particular the Google Auth Platform data-policy checkbox/Finish is owner-only. After they finish, resume with `--project <public-project-id>` (reported in sanitized logs or saved state) and `--step branding`, then audience/client, or rerun all. `--step` supports project/api/branding/audience/client; client always deposits in the same run. Do not repeat project/client creation after an uncertain submit: inspect provider state first. If Google hides an existing secret, **never rotate or create a duplicate automatically**; use the owner-only manual credential form instead. Unknown UI/timeout fails closed.
8. After `deposit: ok`, call `google_app_setup_status` again and require `configured: true` plus the same redirect URI. Do not claim setup from a successful POST alone. Report: “Your Google app is set up. It can connect all your Google accounts.” No IDs or implementation details needed. Retire the private takeover as its host requires; the script intentionally does not close the shared browser.
9. In Connected accounts → **Your Google accounts — add as many as you like**, the owner chooses Connect Google for each account, then **Let Calendar read this account**, grants Google's read-only permission, and explicitly **Allow Calendar to use this account**. App setup does not preauthorize reading accounts or bind Calendar. Explain that a personal “unverified app” warning is expected; In production avoids Testing's 7-day refresh-token expiry but is not public verification.

If browser automation cannot safely proceed, use **Set it up myself**. Guide **one screen at a time**, giving the exact copy value only at its step (redirect URI at step 5). Never replace this with a wall of instructions or ask the owner to paste secrets into chat.

## Calendar consumer API

Calendar uses `X-Wizard-Grant` at `http://wizard-connectors-calendar:8799/service/calendar/` (see `docs/CALENDAR_API.md`). MCP deliberately exposes no calendar lists or events. It also cannot connect accounts or grant service permissions. Music binding remains separate.
