# Connected accounts

Use `connector_status` for content-free readiness and `summary_job_status` for an owner-issued opaque job ID. These tools never return conversations, titles, senders or summaries. Open the human view for fictional chat selection/results. Real chat is not connected. No provider replacement or fallback is permitted.

## Set up the owner's Google app

**Whose account:** the owner's own main Google account owns ONE Google Cloud project and Web OAuth app. Your wizard needs NO Google account. The app is only a permission key, holds no Google data, and connects all the owner's accounts. Default to **External + In production**; only choose **Internal** when the owner is a company Workspace administrator and wants organization-only access.

1. Call MCP `google_app_setup_status` with `{}`. It returns the exact redirect URI, configured/managed flags, required APIs/scopes and `agreements: {accepted, version, country}` — no client credentials. If already configured, do not create or replace anything. Before starting an unconfigured app, require version **google-2026-11**, accepted IDs **cloud_terms, api_terms, user_data_policy**, and a country. Otherwise STOP and tell the owner: “Open Connected accounts → Google → Let your wizard set this up, read Google's agreements, tick the three boxes and choose your country.” Never manufacture acceptance or ask for it in chat.
2. Before creating anything, check that the returned redirect matches the owner's actual public HTTPS Wizard route (or deliberate local loopback install). Fresh installs use `https://<host>/connected-accounts/api/google/callback`; an existing saved redirect, including a legacy route, must be preserved exactly. Never register a guessed address or replace a saved one.
3. Use **hermes-human-handoff**: check `doctor`, then `start --purpose oauth --ttl 3600 --url https://console.cloud.google.com/auth/overview` in its default **fresh disposable profile** mode. Do NOT use `--persistent-profile`, `--profile-template`, the shared Wizard Browser, or `BROWSER_CDP_URL`. Use the supported verified private phone takeover. Ask the owner to sign into **their own main Google account**, typing password and 2FA themselves, then tap Done after the page advances. The agent never types, reads or sees either value. Pause ALL screenshots, DOM/accessibility reads, OCR, console/trace/recording, history and automation during takeover. They do not need to tick the already-recorded agreements. The host owns this one temporary session, not a persistent Google login.
4. Pass the exact MCP agreements object as JSON in **GOOGLE_SETUP_AGREEMENTS** to the shipped `scripts/google_cloud_setup.py`. Stage the shipped source tree with its `app/google_agreements.py` registry, not a rewritten/copied single script. Run only through `hermes-human-handoff run <session_id> <shipped-script> ...`, which injects `HANDOFF_SESSION_ID` and `HANDOFF_CDP_URL`. Run on the same host as its owner-only handoff metadata and CLI. Python Playwright is required. The script verifies the profile mode and endpoint before any browser inspection; no ambient CDP fallback is allowed. `--allow-persistent-profile` is a diagnostic exception requiring explicit owner approval, never the normal setup path; a retained profile cannot pass final removal verification. Never enable tracing/debug/page dumps: credentials appear on the creation screen. An optional `--dry-run` is diagnostic only: it never accepts terms and still retires its disposable session. Do not run it first in the normal one-sign-in setup path.
5. Call MCP `google_app_setup_begin` with `{}` after sign-in. Recheck its agreements object and exact redirect; pass its single-use 30-minute internal intake capability and redirect as **GOOGLE_SETUP_INTAKE_URL**, **GOOGLE_SETUP_REDIRECT_URI**, plus **GOOGLE_SETUP_AGREEMENTS**. A new begin invalidates the old capability. Run in the Wizard service network where `wizard-connectors-calendar:8799` resolves, or through a private loopback tunnel to that ingress; never expose intake through a public route.
6. Run the shipped script with default `--step all`. It accepts ONLY the recorded, version-matched Google agreements, picks the recorded country, and leaves optional marketing emails unticked. It reuses an existing Wizard project/client, enables Calendar API, fills branding/contact from the signed-in owner, chooses External and publishes to production, creates Web client Wizard with the exact redirect, and deposits ID/secret **directly** into Connected accounts. No secrets are printed, saved in its public-project-only state file, copied through a clipboard, or returned by MCP. The broker remains the only credential writer.
7. A JSON `needs_owner` is a STOP, not permission to guess. Any new/unrecorded agreement, version mismatch, changed/unknown UI, identity verification or billing prompt stops. Billing is not needed: never purchase, start a trial or add a payment method. The script signs out if possible and destroys its temporary session on every exit, including failure. Resolve the reported blocker through the owner’s own browser or a fresh disposable takeover, with inspection paused; never restart an uncertain creation without checking status. Never automatically agree to a new document or rotate a hidden secret. After resolution resume with the public project ID and `--step project|api|branding|audience|client`, or rerun all; do not repeat an uncertain creation step.
8. After `deposit: ok`, the script must sign out of Google in that session, stop the handoff, re-read `status: stopped`, and verify the disposable profile and capability files are gone. Require `sign_out: ok`, `teardown: ok`, then `setup: ok`; any failure is `needs_owner` and is NOT completion, even if the app was deposited. Independently read `hermes-human-handoff status <session_id>` and verify stopped/no cleanup error plus profile removal, without dumping browser data or raw cleanup messages. Then call `google_app_setup_status` again and require `configured: true` plus the same redirect. Do not claim setup from a successful POST alone. Report: “Your Google app is set up. It can connect all your Google accounts.” No IDs or implementation details needed. If teardown failed, tell the owner that the temporary Google session could not be verified closed, stop the exact handoff and verify removal before claiming completion. Never retain a Google password or logged-in browser profile.
9. In Connected accounts → **Your Google accounts — add as many as you like**, the owner chooses Connect Google for each account, then **Let Calendar read this account**, grants Google's read-only permission, and explicitly **Allow Calendar to use this account**. App setup does not preauthorize reading accounts or bind Calendar. A personal “unverified app” warning is expected; In production avoids Testing's 7-day refresh-token expiry but is not public verification.

If automation cannot safely proceed, use **Set it up myself**. The manual flow links the same three agreements; the owner clicks Google's own checkboxes. Guide **one screen at a time**, giving the exact copy value only at its step (redirect URI at step 5). Never ask the owner to paste secrets into chat.

## Calendar consumer API

Calendar uses `X-Wizard-Grant` at `http://wizard-connectors-calendar:8799/service/calendar/` (see `docs/CALENDAR_API.md`). MCP deliberately exposes no calendar lists or events. It cannot connect accounts or grant service permissions. Music binding remains separate.
