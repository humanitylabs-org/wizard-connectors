# Assurance and deployment gate

This is a **simulated private-chat preview**, not real-chat eligible. Fictional messages are classified private. Google account authorization is a genuine configurable broker, configured by each owner in Your Google app; GOOGLE_DISABLED=true is the kill switch. No real Google authorization is claimed. See GOOGLE_RELEASE.md for custody, configuration, install and evidence boundaries.

## Implemented
- Deterministic whole-request admission; invalid labels block; private input never chooses the ordinary provider. Private preference fixed to the selected Tinfoil/glm-5-3 route.
- SDK attestation before/after inference; max_retries=0; no tool schemas, agent harness, arbitrary URL, recipient or read-set output; tool calls rejected.
- Separate owner HTTP session and content-free MCP authentication; no conversation/sender/title/result tool. JSON-only mutations and Host/Origin checks; no permissive CORS. Place behind the authenticated same-origin app route.
- Immutable snapshot, stable IDs, one conversation, fixed byte-bounded fixtures, deduplication, bounded output and concurrent job admission. Cancellation, epoch changes and expiry gate delivery.
- Plain-text renderer with strict same-origin CSP, no Markdown or external assets. Fifteen-minute memory-only result retention; no result database, diagnostics or notification side channel. Expired bytes are cleared on subsequent access and all results clear on restart. Policy persists separately; no backup/export defaults.
- Account/grant/binding separation, consent and operation checks, wrong-account refusal, serialized expiry refresh, local unlink vs disconnect, shared-grant reauthentication invalidation in fixture-tested core.

## Google app setup intake
Authenticated MCP `google_app_setup_status` exposes only configured/managed flags, redirect and required API/scopes plus accepted agreement IDs/version/country. `google_app_setup_begin` mints one 30-minute, digest-only, memory-only capability; reissue/restart/manual client save or removal invalidates it. The fixed internal ingress/loopback endpoint consumes it under the broker lock before credential validation. It rejects browser/proxy headers and public Host values, accepts only the two credential fields, and returns only `{ok:true}`. Provider credentials stay out of MCP, browser-control logs, page dumps and script files; the broker's encrypted atomic store remains the sole durable custodian. See GOOGLE_SETUP.md for the precise trust boundary and Playwright/human-gate contract. Real Google Console execution is not yet proved.

## Google app setup sign-in
- **What the model sees:** allowlisted setup/status/reason codes only, never page content, personal account details, cookies, credentials or raw cleanup errors. The local task may read the minimum Console controls and move the new app key directly to the broker without returning it to agents.
- **Password and 2FA:** never seen or typed by the agent. The owner enters both themselves during private Human Handoff takeover. All screenshots, DOM/accessibility reads, OCR, history, console/trace/recording and automation are paused until the owner reports completion and the page advances.
- **Google session:** start `hermes-human-handoff` in its default fresh empty disposable-profile mode, not a shared Wizard Browser, template clone, persistent profile or `BROWSER_CDP_URL`. The script verifies the selected session's private profile metadata and injected endpoint before connecting. Persistent and cloned profiles are unconditionally refused; no bypass flag exists.
- **After deposit:** sign out of Google in that session; verify the signed-out screen and absence of Google authentication cookies locally; then stop the exact handoff, re-read `status: stopped` with no cleanup error, and verify the profile, capability and temporary viewer files are removed. A failed sign-out still triggers stop/deletion. Failed or unverified teardown is `needs_owner`, never setup success. All terminal setup exits retire the verified temporary session, including failed setup and diagnostic dry runs. Active owner sign-in/identity-verification pauses under the original TTL with inspection stopped; it is not setup completion. Local profile deletion is not provider token revocation. The skill requires an independent stopped/removal readback before completion.
- **Afterwards:** Wizard has no Google password or logged-in Google browser session. It retains only the app connection credentials and separately owner-authorized read-only Calendar/YouTube permissions, encrypted in the broker and never shown to agents. App creation itself grants no access to a Google account; each account and service binding still requires the owner's separate approval. No Gmail, Drive, write, billing or account-management access is granted by these read-only permissions.

The installed handoff CLI/metadata contract was inspected, but real Google sign-out and real profile deletion are not claimed by synthetic tests; those require isolated host/browser acceptance. Host administrators remain within the trusted boundary.

## Google agreements and portable origins
`POST /api/google/agreements` uses the existing owner authentication, JSON-only, Host/Origin and cross-site checks. Exact fields only: `agreements` must contain all three known IDs, `version` must be `google-2026-11`, and `country` must be an ISO country code from the server list. The broker adds `accepted_at` and atomically saves in the existing encrypted store before acknowledging. Failed storage changes no in-memory acceptance. GET owner state and authenticated MCP status/begin expose only IDs/version/country, not the timestamp or credentials. Deleting/replacing the Google app leaves recorded agreements intact; it does not grant account access or service binding.

The script consumes the MCP object, never chat/page-asserted delegation. Whole checkbox labels and official legal links must match the recorded document IDs/version before any legal write; unknown forms/documents stop. Country is selected from the record and optional marketing emails are unticked. Identity checks, billing and unknown UI remain `needs_owner`; a dry run never ticks boxes. Reason codes are explicitly allowlisted and exceptions/page contents are not logged. Matching a document's canonical URL is not a cryptographic snapshot of Google's text; a changed URL/label/version stops and this version must be reviewed before broad release.

Fresh installs allow the current Host and require browser mutations to have a same-host Origin (or an explicitly configured trusted origin), behind the authenticated Wizard gateway. `WIZARD_TRUSTED_HOSTS` and `WIZARD_TRUSTED_ORIGINS` remain optional stricter installer pins. No forwarded Host is trusted. Redirects default to same-host HTTPS plus validated route prefix `/connected-accounts/`; saved redirects are never silently rewritten. Internal credential intake retains its separate fixed-host/proxy-header rejection regardless of portable owner-page defaults.

## Not proved / deliberately disabled
Host administrators and unrestricted host agents can read runtime secrets and private memory. Containers are non-root/read-only with no Docker/home mounts. UI internet egress is denied by internal Docker networks; broker/private-worker/media-worker are separate processes/volumes/networks with fixed application-level outbound operations, not destination-firewalled or host-admin-resistant. Actual handlers, encrypted custody, signed ID validation, refresh and revocation are exercised with explicitly fake provider transport; personal Google consent remains unproved. No live chat adapter or official YouTube audio-delivery entitlement is claimed. Existing Music source is untouched. This app is not a replacement for shared Account Manager.

## Review repair
Generic Connect flows are invalidated on disconnect alongside matching reconnects. Media download/probing runs only in the credential-free media-worker container, with no mounts, no broker/private tokens, a disjoint network lane, and allowlisted subprocess environment. The broker no longer offers audio_probe. Real HTTP regression tests cover late unidentified callbacks, RPC operation/token separation, UI-to-media dispatch and both subprocess environments. Exact-image runtime probes must additionally verify actual mounts, env key names, role operation refusal and network reachability.

## Installer contract
Build only from a pushed revision on the designated worker. Pin the exact image. Inject credentials using the normal form into only the service needing them; never commit credentials or mount a Google cookie jar. Supply approved WizardApp core at `/wizard-os-home/core/app-client.js` and register using actual App Manager lifecycle. Staging does not register production. Parent integration must verify cold in-shell open, route owner authentication and stop/uninstall without data deletion. Google connect returns `google_configuration_required` until the owner saves a Google app (or the installer supplies the environment triple) and the broker has its store key/derived secret. The default-off review flag is obsolete. Calendar data always requires a matching Calendar grant, even when enforce=false; see CALENDAR_API.md.
