# Google broker release / parent gates

This is an implemented configurable authorization-code + S256 PKCE broker, **not a claim that a real Google account has authorized this app**. Real activation defaults off. Synthetic chat stays on the original attested Tinfoil/glm-5-3 route. No live shell or Music source is modified.

## Exact account gate

After independent review of the pushed source and exact image, the parent provisions:

1. A **Google OAuth Web application** client owned by the intended project, with client ID **and client secret**. An existing CLI client ID or Gmail grant is not sufficient evidence of compatible client registration. Do not import gog, browser profiles or cookies.
2. One exact authorized redirect URI matching the installed app's authenticated reverse-proxy route: `https://<approved-host>/<actual-app-prefix>/api/google/callback`. The app consumes `/api/google/callback` after prefix stripping. A localhost HTTP callback is permitted for an explicitly registered local test, not as an invented hosted callback. Register before authentication. TLS proxy must not log callback query strings or Authorization headers.
3. Consent screen/audience, and the intended Google user as test user when in Testing. Initial scopes: `openid email`. A separate owner-click incremental request adds only `https://www.googleapis.com/auth/youtube.readonly` for the YouTube Data API catalog operation; enable **YouTube Data API v3** on that project before using it. This grants neither YouTube Music Premium nor audio playback authorization. Testing refresh-token limits/provider revocations apply.
4. `GOOGLE_STORE_KEY`: Fernet key from `Fernet.generate_key()` (32 random bytes URL-safe base64 encoded); retain separately from the encrypted volume. Configure `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, then `GOOGLE_REVIEW_APPROVED=true` only after exact-head review. Missing fields return `google_configuration_required`. Lost/wrong key with existing state refuses startup rather than discarding credentials.
5. Human clicks Connect Google → Continue to Google in a normal browser tab → consent → closes the callback tab → Refresh accounts. Separate account-specific reauthentication checks stable verified `sub`; read-only catalog permission and Music binding are separate actions. Decline, expired state, wrong browser, replay and wrong account fail closed.

No live client/secret/registered redirect was present in this task's runtime configuration. Client metadata elsewhere is not authorization to reuse another application's grants.

## Legitimate installation route (parent-owned)

Actual WAM `wam.cli.install` → `resolve_any` → `private.prepare` supports `humanitylabs-org/wizard-connectors` from private GitHub using the installing host's existing GitHub authority. `private.prepare` fetches repository **HEAD**, not a supplied feature ref: parent must verify HEAD resolves to the reviewed commit, or use the approved release branch/default-head process. Do not change protected/default refs just to bypass this.

The app includes normal Runtipi `form_fields`, consumed by `build_form` and `rt.install`; credentials are mapped only into their service. WAM generates required password fields if not supplied and saves them under its private secrets directory (0600). Five distinct tokens are required (human, MCP, typed Music adapter, broker, private worker). The Google encryption key is optional at initial guarded install and is not auto-generated by WAM's generic password generator (that produces the wrong key format).

Install target must first have the reviewed image loaded, and the local alias `wizard-connectors:reviewed` pointing to it; `private.prepare` preflights this compose default before resolving owner form overrides. Then pin the actual immutable image ID through `CONNECTORS_IMAGE`. Transport the compressed image from the build worker; do not rebuild unreviewed bytes. Example nonsecret command:

```
docker load -i wizard-connectors-<revision>-image.tar.gz
docker tag sha256:<verified-image-id> wizard-connectors:reviewed
wam install humanitylabs-org/wizard-connectors --set CONNECTORS_IMAGE=sha256:<verified-image-id>
```

Configure optional secrets via the installer's confidential form or an in-process `wam.cli.install(config, repo, given=<values read from a 0600 file>)`; **do not put secrets in command-line argv, chat, logs or receipts**. `WIZARD_TRUSTED_HOSTS/ORIGINS` must match the real proxy. `PRIVATE_ROUTE_CONFIGURED=true` only when the Tinfoil key is provided. Read back the WAM registry, runtime image IDs, routed health and cold in-shell app link. Stage-only and the loopback QA proxy are not installation. Builder's single-container staging ignores this four-service production topology and therefore is not a valid runtime proof for this release.

Named `ui-data` / `google-data` volumes are project-scoped; stop/restart preserves them. Avoid `down -v` unless owner explicitly requests account-data deletion. Google broker is the only volume/key/token custodian. UI and private worker do not mount Google state. No host homes, sockets, privileged mode or shared cookies. Every service runs UID1000, read-only root, dropped capabilities, bounded tmpfs and no-new-privileges. UI has only internal networks; broker and private worker have separate outbound lanes, fixed typed operations and no generic authenticated-fetch RPC. Outbound destination allowlisting is application-level, **not a host-admin-resistant firewall**. Host Docker/SSH administrators remain trusted and can inspect environment/volumes. Real private chat eligibility remains false.

## Broker semantics

The credential-free ingress is the Runtipi main service. Docker does not publish ports on a container attached only to internal networks; ingress bridges the owner route to the UI's internal network without injecting authentication or gaining Google/Tinfoil credentials. UI itself has no internet default route.

The isolated Music integration endpoint is `POST /service/music/catalog`, JSON `{"video_id":"<11-char ID>"}`, bearer `MUSIC_ADAPTER_TOKEN`. Only the separately installed Music adapter receives that token after review; never share owner/MCP tokens. The broker selects the account from its persisted owner-approved Music binding; caller-supplied account, scope, URL or operation fields are rejected. It cannot initiate consent, read account lists/private chat, or resolve playback. This is the runnable integration seam; the live Music source is deliberately not patched/activated by this slice. To activate later, configure its reviewed adapter against the installed route, then verify its exact lineage separately.

The broker persists encrypted account/grant/binding snapshots with fsync + atomic replace (0700 directory, 0600 file). Access/refresh tokens never return via UI or MCP. OAuth state/nonce/verifier are ephemeral for 10 minutes; browser binding uses a separate HttpOnly SameSite=Lax cookie while the owner session is SameSite=Strict. Only the callback permits cross-site navigation, and it never unlocks the human UI. Token validation verifies RS256 signature, issuer, audience, azp, expiry/iat, nonce and stable subject; granted scopes cannot exceed supported scope set or omit requested scopes. Refresh, catalog calls, unlink and disconnect serialize under the broker lock. Nonce and code cannot be replayed after callback attempt. Unlink keeps the account; disconnect removes local credentials first and explicitly reports provider revocation success/failure. On revocation failure/pending crash, human must remove this app from Google account permissions.

Catalog operation is fixed `videos.list(part=snippet,id=<validated 11-char ID>)` through YouTube Data API, not a claimed YouTube Music library API. Music binding permits only `catalog.lookup`, never Gmail or playback. Existing Music remains at its existing source. Independent `audio-probe` uses pinned yt-dlp with no configuration/cache/cookies and validates actual fresh audio bytes with ffprobe, or reports a structured provider sign-in/source/timeout failure. It never reports catalog metadata as audio. A successful fresh download is still **not browser playback proof**.
